# CoursePilot — test log

Before releasing this version, I tested the course planner, account workspace, review display and new SIS calendar import. The JavaScript suite ran 48 checks, including data integrity, date-limited conflicts, impossible preferences, calendar export and independent account saves. I also ran the 16-check desktop timetable browser suite and a browser import scenario against a local Supabase fixture. The latter uploaded a sample `.ics` file, checked its room and instructor, cleared selections, refreshed, and signed in as another user to check isolation.

For the calendar parser, I used synthetic SIS-style events with a weekly recurrence, an unrelated appointment and an invalid file. I checked the two recurring Hong Kong dates, skipped the unrelated event, and confirmed invalid input retained the timetable. I then locked a conflicting accounting lecture and confirmed the planner returned no complete plan. A compatible plan can still be generated around fixed classes. The exported sample week includes the locked meeting at its actual local time.

One bug appeared during implementation: a calendar event labelled `Asia/Hong_Kong` was initially interpreted as UTC when the file omitted a timezone definition. This shifted the class by eight hours. I registered the Hong Kong timezone explicitly and added a regression assertion for 13:30–14:50 local time. I also found that normalizing the description before extracting the instructor could swallow the next line, so I changed extraction to read the original line breaks.

I did not test with a real student's SIS export or perform a real enrollment action; the fixture checks frontend account isolation but cannot prove production email delivery or database policies. CoursePilot therefore asks users to compare imported rooms, teachers and times with SIS. GitHub Pages has no Python application server, so the file is parsed in the browser and only the resulting meetings are saved to the user's Supabase workspace.
