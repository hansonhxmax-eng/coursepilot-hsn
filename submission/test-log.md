# CoursePilot — pre-release test log

We tested two clearly separated workflows: planning with uploaded 2026–27 Fall schedule snapshots, and the original preference demonstration with synthetic reviews. Eleven image-only PDFs, totaling 117 pages, produced 462 detected courses and 1,168 section records. These are OCR results, not a claim of complete or error-free SIS coverage.

Validation included 36 JavaScript tests, 11 Python collector-helper tests, 18 real-workspace browser checkpoints and 20 preference-demo browser checkpoints. Tests covered unique identifiers, source checksums, valid time intervals, date-limited meetings, overlapping and adjacent sessions, required lecture/tutorial/lab components, section locks, campus-day limits and bounded-search reporting. Unknown attendance, quizzes and group-work fields correctly blocked unsupported hard constraints. TBA-only courses and unverified component matching were excluded rather than presented as complete schedules.

Browser testing checked department filters, course search, PDF links, three alternative section plans, conflicting locks, empty-state recovery, calendar exports, course-selection persistence, review imports and desktop/mobile layouts. Exports preserved actual durations, including an 80-minute accounting session and a 110-minute AI-literacy session. Invalid dates and malformed imports were rejected. Imported text was rendered literally, including a script-shaped test string, and remained local to the tab.

We found that text extraction returned no course text because the PDFs contained images, so we added OCR and source-page links. Testing also exposed an OCR-label validation gap that could admit ambiguous section labels; we fixed it and added regression coverage. Narrow corrections were recorded only for fields checked against source images. Calendar input now rejects non-Monday weeks.

The local review collector passed helper tests and a simulated-browser pagination test. Authenticated USTSpace compatibility and real review completeness remain untested until the account owner logs in locally. We deliberately retained visible-content-only labels, conservative stopping on access restrictions, unknown review-derived academic attributes and historical seat counts. Public uptime across the review window and real enrollment outcomes are not established by these tests.
